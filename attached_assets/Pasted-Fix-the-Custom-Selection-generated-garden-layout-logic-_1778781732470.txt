Core requirement:
When the user chooses Custom selection, the generated plan must use only the plants the user selected, plus any custom plants they manually added. It must not auto-add unselected categories or default/generic plants.

Make sure the selected plant IDs/categories are actually passed into the generation function and used when building the output.

2. Custom selection must be strict

When garden goal/type is “Custom selection”:
- Treat selected plants as the source of truth.
- Do not use the default recommended plant set.
- Do not use a generic garden map.
- Do not fill open spaces with unselected plants.
- Do not auto-add vegetables, herbs, or flowers unless the user selected them.
- If only flowers are selected, the generated map must show only flowers.
- If only herbs are selected, the generated map must show only herbs.
- If only vegetables are selected, the generated map must show only vegetables.
- If a mix is selected, the generated map must show only that selected mix.

3. Pick My Plants category behaviour

Each category-level “Pick My Plants” button must only select plants from that category:
- Flowers → only flowers
- Herbs → only herbs
- Vegetables → only vegetables

If the user clicks “Pick My Plants” under Flowers and does not select anything else, the generated plan should contain only flowers.

If the user clicks Flowers + Herbs, the generated plan should contain only selected flowers and selected herbs.

4. Manual selection behaviour

Manual checkmarks must be respected:
- If the user manually selects Marigolds, Nasturtiums, Calendula, Pansies, and Violas only, those should be the only plants considered for the generated layout.
- Do not add plants from the whitelist just because they are suitable.
- Do not add filler plants.

5. Make the layout dynamic and smart

The generated garden map should not be a static template.

It should dynamically build the map based on:
- selected garden area(s)
- dimensions
- unit system
- sunlight level
- soil/container type
- selected plants
- custom plants
- available space

For Custom selection:
- place the selected plants intelligently across the available grid
- repeat selected plants if space allows and it makes sense
- leave empty cells if there are fewer selected plants than spaces
- do not fill empty cells with unselected plants
- if a selected plant is unsuitable for an area, either:
  - place it with a gentle caution note, or
  - exclude it and show a note explaining why
- do not replace unsuitable selected plants with unrelated unselected plants unless the user explicitly chose a recommendation goal rather than Custom selection

6. Empty custom selection handling

If the user chooses Custom selection but selects no plants and adds no custom plants:
- prevent generation
- show:
  “Select at least one plant, or choose a recommended garden goal.”
- Do not generate a default mixed garden.

7. Non-custom recommendation goals should still work

Do not break the recommendation logic for other garden goals:
- Beginner-friendly
- Vegetable-focused
- Herbs & Flowers
- Pollinator-friendly
- Family / Kid-friendly

For those non-custom goals, GrowIt may recommend plants based on the garden inputs.

But for Custom selection, the output must follow the user’s selections.

8. Update all generated outputs

The selected-plant filtering must apply consistently to:
- generated plan data
- garden map
- plant table
- weekly schedule
- downloaded plan
- shared plan summary

There should not be a situation where the map shows unselected plants while the plant list shows selected plants, or vice versa.
